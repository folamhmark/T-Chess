# Задачи дня — спецификация экрана, состояний и анимации

Версия 1.2 · 19 ноября 2026.

Документ фиксирует согласованный веб-прототип **без блика на прогресс-баре**. Это handoff для дизайна, разработки и QA. Реализованное поведение описано в разделах 1–11; ограничения и рекомендации для продуктовой интеграции вынесены в разделы 12–14 и не являются утверждёнными серверными правилами.

Прототип показывает зачёт задачи, рост прогресса и переход между задачами, а после пятой задачи — анимацию завершения.

Карточка, счётчик, бабл, клетки и шторка реализованы в HTML/CSS. Фигуры и иконки используют SVG из Figma, встроенные в HTML. Для текста карточки, первой реплики и доступных в макете цифр счётчика используются контуры из Figma. Пингвин и снежная шапка используют два отдельных прозрачных PNG 2× из Figma.

Стек: статический HTML, CSS, JavaScript, локальная Anime.js 3.2.2 (MIT). Установка зависимостей, сборка и сервер приложения не нужны. Хостинг — GitHub Pages, каталог `daily-tasks-animation` в `folamhmark/T-Chess`.

**В прототип не входят:** проверка шахматных ходов, перемещение фигур, реальное решение задач, неверный ход, движок, авторизация, серверное сохранение результатов, награды, звук и haptic. Кнопка «Завершить задачу» имитирует успешный результат.

## 2. Согласованные принципы

1. Геометрия и графика экрана следуют указанным узлам Figma.
2. Управление демонстрацией вынесено за пределы телефона, справа на широком экране.
3. У счётчика меняется только цифра; подпись «из 5» остаётся на месте.
4. Бабл появляется целиком: лёгкий подъём, увеличение и проявление с мягким торможением. Пружинного отскока нет.
5. Текст плавно раскрывается по символам с перекрытием; строка заранее занимает итоговое место. Постепенного дописывания строки с пересчётом переноса нет.
6. Прогресс растёт плавно, однотонным синим заполнением. **Блик, светлая грань, перелив и дополнительные декоративные слои отсутствуют.**
7. Шторка «Верный ход» появляется поверх нижней части доски. Затемнение и размытие экрана под ней отсутствуют.
8. В задачах 1–4 кнопка «Ого, погнали дальше» открывает следующую задачу после закрытия шторки. На пятой задаче «ОК» запускает финальную анимацию.
9. Паттерны Apple / Duolingo задают характер движения; конкретные кривые и времена определены ниже. Это не утверждение об использовании их внутренних animation API.

## 3. Данные и смысл показателей

| Поле | Тип / диапазон | Начальное значение | Назначение |
| --- | --- | --- | --- |
| `current` | целое 1…5 | 1 | Номер показанной задачи |
| `completed` | целое 0…5 | 0 | Число зачтённых задач текущего демонстрационного круга |
| `sheetOpen` | boolean | false | Шторка участвует в открытии, показе или закрытии |
| `sheetClosing` | boolean | false | Защита от повторного запуска закрытия |
| `token` | возрастающее целое | 0 | Версия запуска анимации задания; защищает от устаревших callback |
| `active` | массив animation handles | [] | Анимации счётчика, бабла, текста и шторки, которые можно остановить |
| `reduced.matches` | boolean | системное | Предпочтение уменьшения движения |
| `slow` | boolean | false | Демонстрационный множитель времени ×3 |

Верхняя карточка показывает **номер текущей задачи**, а не число завершённых. Например, при `current=2`, `completed=1` на карточке написано «2 из 5», прогресс равен 20%. При открытии результата второй задачи карточка ещё показывает «2 из 5», а прогресс уже идёт к 40%.

Формула заполнения: `P = clamp(completed, 0, 5) / 5`. Ширина дорожки — 140 px, поэтому одно задание добавляет 28 px / 20 процентных пунктов.

| Состояние | `current` | `completed` | Подпись | Целевое заполнение |
| --- | --- | --- | --- | --- |
| Вход | 1 | 0 | 1 из 5 | 0% / 0 px |
| Первая задача зачтена | 1 | 1 | 1 из 5 | 20% / 28 px |
| Открыта вторая | 2 | 1 | 2 из 5 | 20% / 28 px |
| Вторая зачтена | 2 | 2 | 2 из 5 | 40% / 56 px |
| Третья зачтена | 3 | 3 | 3 из 5 | 60% / 84 px |
| Четвёртая зачтена | 4 | 4 | 4 из 5 | 80% / 112 px |
| Пятая зачтена | 5 | 5 | 5 из 5 | 100% / 140 px |
| Продолжение после пятой | 1 | 0 | 1 из 5 | 0% / 0 px |

Данные хранятся только в памяти страницы. Перезагрузка возвращает первую задачу и нулевой прогресс. Дата «17 августа» в карточке — статичный текст макета, не текущая дата пользователя.

## 6. Состояния и переходы

Состояния ниже — смысловая модель для handoff. В коде они выражены отдельными полями и callback, а не одним enum.

| Состояние | Что видно | Допустимые действия | Выход |
| --- | --- | --- | --- |
| `task/initial` | Задача 1, полный текст, прогресс 0%, шторки нет | Завершение, выбор задачи, повтор | Результат либо смена задачи |
| `task/ready` | Текущая задача, бабл и цифра в покое | Те же действия | Результат либо смена задачи |
| `task/changing` | Смена цифры, уход старого бабла, появление нового текста | Можно выбрать другую задачу, повторить или завершить текущую логическую задачу | Последний актуальный запуск либо результат |
| `result/opening` | Шторка поднимается, прогресс растёт | Кнопка продолжения уже доступна; Escape | Показ либо досрочное закрытие |
| `result/open` | Полная шторка «Верный ход» | Продолжить или Escape | Закрытие |
| `result/closing` | Шторка уходит вниз | Повторное закрытие игнорируется | Следующая задача либо возврат к текущей |
| `cycle/finishing` | Закрывается шторка, пингвин ныряет, сцена растворяется | Переключатель ×3 | Раскрытие экрана успеха |
| `cycle/revealing` | Белая пауза, затем снежная маска раскрывает пингвина, заголовок, подпись и действие | Нажатие после появления действия | Экран успеха или новый круг |
| `cycle/complete` | «Задача дня решена!», зачтены 5 из 5 задач | Коснуться экрана, начать заново, повторить финал, выбрать задачу | Первая задача, результат пятой задачи или выбранная задача |

### 6.1. Вход

При загрузке сразу показаны первая задача и полный текст. Анимации появления бабла при первом входе нет. Прогресс устанавливается в 0% без движения, шторка скрыта. Автоматического перехода по таймеру нет.

### 6.2. Завершение задачи

1. Нажатие «Завершить задачу» вызывает `showResult()`.
2. Если шторка уже открывается, показана или закрывается, повторный вызов игнорируется.
3. Текущие анимации задания останавливаются; цифра и текст приводятся к содержимому текущей логической задачи.
4. `completed` присваивается `current`, а не увеличивается через `+1`. Поэтому повторное открытие результата после Escape не добавляет лишнюю задачу.
5. Прогресс начинает двигаться к новому значению; одновременно начинает появляться шторка.
6. Блокируются цифры выбора, «Завершить задачу», «Повторить анимацию», подсказка и кнопка назад. Переключатель ×3 остаётся доступен.
7. Кнопка шторки доступна сразу. По окончании открытия получает фокус.

### 6.3. Продолжение

1. Нажатие «Ого, погнали дальше» или «ОК» запускает `closeResult(true)`.
2. Устанавливается `sheetClosing`; сама кнопка отключается. Повторный тап ничего не меняет.
3. Незавершённое открытие, если оно ещё идёт, прекращается; шторка уходит из текущего положения вниз.
4. Шторка скрывается после закрытия. В задачах 1–4 панель управления разблокируется в этот момент, в задаче 5 — после анимации экрана успеха.
5. Для задач 1–4 запускается `go(current+1, false, true)`: номер растёт, текст меняется, зачтённый прогресс сохраняется.
6. После «ОК» на задаче 5 пингвин уходит вниз за снег, сцена растворяется в белый и открывается экран «Задача дня решена!». Результат 5 из 5 сохраняется до запуска нового круга или выбора задачи.
7. Фокус возвращается на «Завершить задачу» в задачах 1–4. После финала фокус переходит на заголовок экрана успеха. Tab ведёт к «Коснитесь, чтобы продолжить».

### 6.4. Escape

Escape при открытой или открывающейся шторке запускает закрытие без перехода. После закрытия остаются текущие номер и текст; уже зачтённый прогресс сохраняется. Во время закрытия повторный Escape игнорируется. Клик по доске и свайп ручки шторку не закрывают.

### 6.5. Выбор задачи и повтор

- Цифры 1–5 вызывают `go(n)`: текущая задача становится n, прогресс — `(n−1)/5`. Это прямой демонстрационный переход, в том числе назад.
- Выбор той же цифры тоже перезапускает переход и задаёт n−1 завершённых. Это может убрать зачёт, сохранённый после Escape: такое поведение относится к панели демонстрации.
- «Повторить анимацию» и кнопка подсказки вызывают `go(current, true)`. Номер остаётся тем же, зачтённый прогресс сохраняется, бабл и цифра повторяют анимацию.
- После финала «Повторить финал» возвращает пятую задачу с открывающейся шторкой. «Начать заново» или нажатие на экран успеха сразу показывает первую задачу с прогрессом 0%.
- Кнопки истории назад/вперёд неактивны. Кнопка назад в app bar не имеет навигационного обработчика в прототипе.

## 7. Спецификация motion

Время ниже приведено при ×1. Все координаты — относительно положения покоя элемента. `cubicBezier(a,b,c,d)` соответствует CSS `cubic-bezier(a,b,c,d)`.

### 7.1. Смена цифры

Отсчёт t=0 — запуск `go()`.

| Слой | Начало | Длительность | Изменение | Easing |
| --- | --- | --- | --- | --- |
| Старая цифра | 0 | 180 мс | opacity 1→0; Y 0→−14 px при ходе вперёд | `easeInQuad` |
| Новая цифра | 130 мс | 390 мс | opacity 0→1; Y +18→0 px при ходе вперёд | `(.22,1,.36,1)` |

При переходе к меньшему номеру знаки Y обращаются. При повторе того же номера используется направление вперёд. В интервале 130–180 мс обе цифры могут присутствовать с разной прозрачностью; обе ограничены одним окном 10 × 20. На t=520 мс новая цифра становится основной, временный слой скрывается. «из 5» не анимируется.

### 7.2. Бабл и текст

| Фаза | Начало от `go()` | Длительность | Параметры | Easing |
| --- | --- | --- | --- | --- |
| Уход старого бабла | 0 | 110 мс | Y 0→+2 px; scale 1→.985; opacity 1→0 | `(.4,0,1,1)` |
| Подготовка текста | после ухода | синхронно | Создать полный новый текст, выставить прозрачность букв 0 и blur 1.2 px | — |
| Геометрия нового бабла | 110 мс | 440 мс | Y +8→0 px; scale .95→1 | `(.16,1,.3,1)` |
| Прозрачность нового бабла | 110 мс | 160 мс | opacity 0→1 | `(.2,0,0,1)` |
| Первая буква | 215 мс | 240 мс | opacity 0→1; blur 1.2→0 px | `(.22,1,.36,1)` |
| Каждая следующая буква | +18 мс относительно предыдущей | 240 мс | Те же параметры | `(.22,1,.36,1)` |

Бабл, хвост и содержимое движутся как один контейнер, а буквы проявляются по очереди внутри него. Для первой реплики анимация проявляет отдельные буквы в исходном SVG, сохраняя интервалы и перенос. Размер бабла 196 × 60 px.

Пусть N — число отображаемых символов без пробелов в текущих демонстрационных строках. Последняя буква заканчивает проявление примерно на `Ttext = 455 + 18 × (N−1)` мс от начала `go()`. Полный визуальный переход заканчивается на `max(520, 550, Ttext)`. Readout панели показывает оценку `455 + 18 × N`, то есть для этих строк на 18 мс больше окончания текста. Это оценка UI, а не дополнительная задержка.

При финализации не заменять уже сформированные span обычной строкой без необходимости: это предотвращает изменение набора/переноса в последнем кадре. Код сохраняет их, если итоговый `textContent` уже совпадает с целевой строкой.

### 7.3. Прогресс

- Триггер: присваивание числа зачтённых задач в `showResult()`. До нажатия продолжения значение уже зачтено.
- Анимация: CSS width от текущей видимой ширины до `completed × 20%` за **620 мс**, easing `(.22,1,.36,1)`.
- Высота 8 px, цвет `#428BF9`, круглые окончания. Прозрачность и цвет не анимируются.
- Прогресс может продолжать движение ещё 160 мс после окончания открытия шторки (620 − 460).
- При новом вызове `setProgress()` предыдущая анимация заполнения отменяется; новая направляется к актуальному значению. Проценты не выходят за 0–100.
- При выборе номера демонстрационной кнопкой допускается движение назад.
- После полного круга значение 100% сохраняется. При нажатии «Начать заново» прогресс сразу сбрасывается в 0%.
- Никаких бликов, светлых полос, пульсации или увеличения толщины добавлять не нужно.

### 7.4. Шторка

| Действие | Значения | Время | Easing |
| --- | --- | --- | --- |
| Появление | translateY +178→0 px | 460 мс | `(.16,1,.3,1)` |
| Закрытие | translateY из текущего положения →+178 px | 260 мс | `(.4,0,.8,.2)` |

Высота шторки неизменна. Отдельного fade, scale, blur, overshoot или bounce нет. Иконка, текст и жёлтая кнопка перемещаются вместе со шторкой. Слой имеет z-index 10 и обрезается рамкой телефона. В закрытом состоянии используется `hidden`, а не только прозрачность.

### 7.5. Замедление ×3

Множитель умножает длительности и задержки при **запуске** конкретной анимации; амплитуды, размеры, текст и целевой прогресс остаются прежними. Например, прогресс длится 1860 мс, открытие шторки 1380, закрытие 780. Изменение переключателя не пересчитывает уже идущий timeline. Новые фазы, создаваемые позже отдельным действием, читают актуальное значение переключателя.

### 7.6. Финал пятой задачи

| Элемент | Время после «ОК» | Движение |
| --- | --- | --- |
| Шторка | 0–260 мс | Закрывается вниз |
| Пингвин | 0–480 мс | Опускается на 100 px под неподвижный слой снега и за край доски. Easing `(.42,0,.56,1)` |
| Сцена | 480–900 мс | Сразу после нырка фон и интерфейс плавно растворяются в белый. Easing `easeInOutSine` |
| Белая пауза | 900–1400 мс | Белая маска закрывает новый экран |
| Экран успеха | 1400–4680 мс | Снежное раскрытие и появление пингвина с лёгким перелётом по таймингу подарка. Заголовок, подпись и действие появляются последовательно. |

Действие «Коснитесь, чтобы продолжить» доступно с 4000 мс. При включённом ×3 полный финал длится 14 040 мс. С уменьшенным движением сразу открывается конечное состояние экрана успеха.

## 8. Прерывание и защита от повторов

`go()` и `showResult()` останавливают зарегистрированные анимации задания. `token` увеличивается; callbacks прежнего запуска не должны подменить актуальные цифру, текст или сообщение статуса. Прогресс управляется отдельно и перенаправляется через `setProgress()`.

Во время смены задания внешние кнопки остаются доступны. Последнее действие определяет актуальное содержимое. Нажатие завершения во время смены засчитывает логический `current`, выставленный в начале перехода, даже если визуально цифра ещё не установилась.

Внутри открытого результата приоритет имеют `sheetOpen` / `sheetClosing`: внешние кнопки заблокированы, дополнительное открытие игнорируется, закрытие выполняется один раз. Раннее нажатие продолжения допустимо. Окончание opening-callback не должно вернуть фокус в уже закрывающуюся шторку.

Повтор результата после Escape присваивает то же количество выполненных задач. Повторное открытие не даёт дополнительный процент. Прямой выбор номера в панели намеренно переписывает число завершённых для демонстрации выбранного момента.

## 9. Уменьшение движения и доступность

### Реализовано

- `prefers-reduced-motion: reduce` при запуске перехода: номер, текст и прогресс меняются сразу; шторка показывается/скрывается сразу.
- Во время включения reduce текущая анимация прогресса отменяется и выставляется целевая ширина. Если шторка закрыта, содержимое текущей задачи приводится к покою через повтор без движения.
- Прогресс имеет `role=progressbar`, имя «Пройденные задачи», min=0, max=5, `aria-valuenow=completed`, `aria-valuetext="Пройдено N из 5 задач"`.
- Цифры выбора имеют `aria-pressed`; настоящая системная кнопка поддерживает клавиатурное нажатие.
- Визуальные счётчик и текст бабла скрыты от скринридера; отдельный `role=status` сообщает задачу после окончания перехода и положительный результат при его показе. Промежуточные буквы не озвучиваются.
- Шторка имеет `role=dialog` и заголовок через `aria-labelledby`. После открытия фокус переходит на продолжение; после закрытия — на завершение задачи справа.
- У кнопки продолжения есть `:focus-visible` outline 3 px `#428BF9` с offset 3 px.
- Шторка не объявлена modal; focus trap не реализован. Переключатель замедления остаётся доступен.

### Ограничения текущей реализации

Включение reduce **посреди** открытия или закрытия уже движущейся шторки не завершает её мгновенно: код обновляет прогресс, но не перепланирует этот timeline. Учитывать это как известный пробел, а не как образец поведения для продакшена. Выключение reduce не запускает анимацию само по себе.

Разделение текста через `Array.from()` подходит текущей кириллице. Для сложных grapheme clusters / emoji / лигатур потребуется сегментация графем; полная типографическая поддержка всех языков не реализована. Масштабирование системного шрифта, контраст всей композиции и focus trap ещё не прошли отдельный аудит.

## 12. Известные ограничения и граница готовности

**Реализовано и согласовано в пределах демо:** текущий motion, палитра, шторка, последовательность пяти задач, отсутствие блика, размещение через GitHub Pages.

**Допущения прототипа:** любое завершение считается успешным; задачи не загружаются; заголовок и дата постоянны; повторный круг нужен для демонстрации; только пять коротких русских текстов.

**Перед продуктовой разработкой требуют отдельного решения:**

| Приоритет | Пробел / риск | Последствие | Предложение, не реализованное в демо |
| --- | --- | --- | --- |
| P0 | Нет серверного/движкового подтверждения результата | Клиентская кнопка не может быть источником реального зачёта | Подключить подтверждённый результат решения; идентификатор операции для повторов |
| P0 | Нет сохранения/восстановления | Reload/kill теряет прогресс | Хранить зачтённые taskId и текущую сессию у продуктового источника истины |
| P1 | Нажатие на экран успеха начинает новый круг демо | Действие после экрана успеха зависит от продуктового сценария | Согласовать маршрут после нажатия |
| P1 | Мгновенные reset стилей при прерывании | Возможен скачок бабла при очень быстрых действиях | В продукте интерполировать из видимого состояния либо блокировать на короткое окно |
| P1 | Reduce меняется во время уже идущей шторки | Она продолжает движение | Завершать существующие timeline в конечное состояние |
| P1 | Длинный текст и увеличенный системный шрифт не покрыты | Фиксированная высота 60 и nowrap-слова могут выйти за контейнер | Согласовать предельный контент и авто-высоту, адаптировать соседние элементы |
| P1 | Неполная клавиатурная/скринридерная модель | Фокус может выйти из результата; фон доступен | Определить модальность и порядок фокуса для целевой платформы |
| P2 | Панель управляет даже незавершённым заданием | Быстрый тап может зачесть уже новый логический current | Не переносить демонстрационные контролы в игровой flow |

Эти пункты не меняют опубликованный прототип и не означают, что новые бизнес-правила согласованы.

## 13. Рекомендуемый контракт продуктовой интеграции

Это предложение для handoff, а не существующий API.

Минимальные данные: `sessionId`, `taskId`, `taskIndex`, `taskCount`, `prompt`, состояние доски, множество `completedTaskIds`, статус результата. `completedCount` выводится из множества подтверждённых задач, а не из количества тапов. `progress = completedCount / taskCount`.

Когда продукт получает подтверждённый успех новой задачи, он один раз добавляет taskId в зачтённые, обновляет прогресс и показывает результат. Повтор той же операции возвращает тот же результат без нового начисления. Закрытие шторки и продолжение не должны отменять зачёт. На ошибке/ожидании ответа нельзя показывать «Верный ход» как подтверждённый результат. Состояния submitting / retry / offline / восстановление требуют отдельных текстов и макетов.

Следующую задачу желательно подготовить до закрытия шторки. Если данных нет, нужен явно определённый loading/error flow; отсутствующее задание нельзя заменять пустым баблом. Для выключенного motion логическая последовательность результата и продолжения остаётся прежней.

Контент задачи принадлежит контентному источнику, проверка успеха — игровому движку/сервису, отображение и временная оркестрация — клиенту. Для локальной игры конкретный источник подтверждения может быть клиентским движком; выбор архитектуры ещё не сделан.

## 14. Рекомендации по измерению и выпуску

Аналитика в прототипе **не реализована**. Для продукта достаточно начать с событий:

| Событие | Условие отправки | Полезные параметры |
| --- | --- | --- |
| `task_viewed` | Новая задача действительно показана | sessionId, taskId, index, total |
| `task_completion_confirmed` | Новый успех подтверждён источником истины | taskId, operationId, completedCount, total |
| `task_result_presented` | Результат видим | taskId, reducedMotion |
| `task_continue` | Принято продолжение | taskId, nextTaskId, completedCount |
| `task_result_dismissed` | Закрытие без продолжения | taskId, reason |

Повторы motion и выбор цифры в демо не являются игровыми успехами. Не отправлять события на каждый кадр/символ. Для подтверждённого результата нужна дедупликация по taskId/operationId.

Документ описывает версию исходников, указанную в разделе 1. Для выпуска сверять фактический JS/CSS, комплектность data URL и GitHub Pages, затем выполнить критерии раздела 11 на целевых устройствах. Изменение времени, контента, финального шага или правила зачёта требует обновления соответствующего раздела спецификации.
